# Discussion Categories — Configuration

Create these in repo **Settings → General → Features → Discussions**, in
this order (GitHub's "New category" flow; slugs are auto-derived).

| # | Category | Type | Description (paste verbatim) |
|---|---|---|---|
| 1 | 📣 Announcements | Announcement (maintainers only) | Releases, roadmap changes, and calls for help from the maintainers. |
| 2 | 💬 General | General discussion | Anything FED-Indeed that doesn't fit a category. |
| 3 | 💡 Ideas | Ideas / brainstorm | Proposals, design debates, roadmap feedback. The best ideas graduate into ROADMAP.md. |
| 4 | 🙏 Q&A | Q&A (mark answered) | Usage questions — ask here, not in issues. Answers stay searchable for everyone. |
| 5 | 👋 Show and tell | Show and tell | Your audits, before/after screenshots (synthetic data only!), deployment stories, and wins. |
| 6 | 😐 Polls | Polls | Community votes — these genuinely reorder roadmap priorities. |

## Notes

- **Announcements** restricted to maintainers (default for the
  Announcement type) — used for releases and the welcome thread.
- **Q&A** uses the mark-answered flow; encourage answer-marking so search
  works.
- **Ideas** is the constitutional front porch: proposals that would touch
  [ADR.md](../ADR.md) commitments (persistence, network, new deps) *must*
  start here, not as a PR.
- **Polls** are low-frequency by design — one live poll at a time,
  please.

The full category etiquette guide lives in
[.github/DISCUSSION_WELCOME_README.md](../.github/DISCUSSION_WELCOME_README.md);
GitHub surfaces it to users when they create their first discussion.
